# 独立 Skill 接入：先识别工作台，再选择执行方法

这是各独立 Skills 共用的接入说明，随包带固定摘要快照。Agent 按说明检查和选择；本文不是自动扫描器、安装程序或第三方适配器。没有 chengfeng-videocut，不等于没有工作台。

## 先判定本次是否需要工作台

纯镜头方案、独立 HTML/SVG 动画、输入已完整的离线候选、交付已有文件或整理 Bug 草稿，按本 Skill 的输入/依赖要求直接处理；不为这些任务查工作台或推荐安装。离线候选也须满足真实输入合同，不能借此绕过正式项目读取和提交。

需要读写项目、集成画面、工作台审核或从工程导出时，先做下面的有限只读检查。同一任务沿用已确认的选择，只在入口、身份、能力变化或调用失败时重查；不每步重新问、不例行查更新。

## 识别已有工作台

1. 先看用户指定的工具和当前项目已有的归属/连接信息，再看宿主当前可用 Skill、工具说明和已知本地安装记录。ChatCut 等也可作为候选，不只寻找我们的 Runtime；用户指定优先，不因存在我们的 CLI 就替换他的选择。
2. 必要时只读查询本地已安装应用名称/登记信息，或核验已知启动器路径。CLI 查找仅针对已知名称；系统 PATH 未命中不能证明软件未装，受管路径、GUI 应用和宿主工具分别核验。不扫描磁盘、端口、其他人的项目，不为“探测”下载程序或执行陌生脚本。
3. 找到候选后，读取它现有的 Skill / 受支持操作说明，以已知入口的只读帮助或连接检查核对本次能力、项目身份、输入输出和权限。网页可开、进程存在、同名命令都不证明任务可执行。没有环境访问或入口不明时标“未知”，向用户问入口，不说“未安装”。
4. 在当前任务上下文保留所选工作台、入口、项目、所需能力及证据；无需新建持久台账或收集完整软件清单。多个合格候选且用户未选择、项目也未绑定时，简短让用户选择，不自动迁移项目。

| 检查结果 | 下一步 |
|---|---|
| 已有工作台，且本任务有验证过的操作方法 | 复用该工作台；先读其方法，再按原授权执行并验收，不重复推荐安装 |
| 已安装但未启动、连不上或权限不足 | 准确报告状态，核对原入口，按授权启动/修复；不叫“没安装”，不另起服务或重装掩盖故障 |
| 只发现应用，缺少调用方法/格式兼容证据 | 说明已装但接入未验证，询问可用入口；不能把它的工程当我们的工程 |
| 无环境访问、检查失败或候选身份不明 | 标未知并补问必要信息，不因此引导重装 |
| 有限检查未发现工作台，或明确不支持本次能力 | 报告范围/缺口。仅当 chengfeng-videocut 的已验证能力能补齐时，询问是否安装；用户也可指定其他工作台或先只做独立结果 |

询问示例：“在当前可检查的范围里，没有找到能完成这一步的本地工作台。是否安装 chengfeng-videocut Plugin（来源 Agentchengfeng/chengfeng-videocut-skills）？也可以告诉我你已有的工作台，或先只生成独立文件。”已有工具但能力不足时，应具体说出缺口，不能套用“没有找到”。未回答或拒绝都不是安装授权；继续能独立做的部分，不能独立做则说明暂停在哪一步，不反复推荐。

## 按选中的工作台分流

- **chengfeng-videocut**：按下节及 [CLI 合同](runtime-cli.md)执行。本包其余 `workbench ...`、Cuts/EDL、wordId、receipt 与 revision 示例均属于这条路线，不是所有工作台通用协议。
- **其他工作台（包括用户所举的 ChatCut）**：只有现有 Skill/受支持接口及实际检查证明可完成本次操作，才交接给该提供者的方法；这些示例不构成 ChatCut 集成承诺。不向它发送我们的命令、JSON 或伪造兼容接口。不支持时暂停工程接入并说明缺口，只有用户明确选择独立模式才交付独立结果；开发适配、转换/迁移项目需另行约定，不能默认回退本产品偷偷执行。
- **已明确选择本产品但本地没有**：说明所需安装范围，取得授权后读受信公开安装说明和固定来源，再准备它。不要求用户先安装一个缺失的维护 Skill 才能判断是否安装。

维护、检查更新和 Bug 上报只处理用户指定的产品/组件，不是每次创作的前置。不自动把第三方故障报到本产品仓库，也不为诊断安装替代品。

## 本产品 Runtime 的调用约束

1. 纯设计、候选和 Bug 草稿不强制连接。工程操作使用用户提供或受信安装记录里的 Runtime 入口、显式 loopback origin 和服务端 projectId；不扫描端口、不猜默认服务、不复制注册。
2. 用实际入口的 `--help`、`workbench commands --json` 和 `workbench connect --api-base <origin> --json` 核对版本、身份和具体能力。版本相同也可能未含新命令，不能只比版本号。
3. 写入依旧需要授权及对应 `--confirmed`，绑定原 revision/hash/operationId。unknown 先查询原操作，不自动重试；不直接改正式项目 JSON。
4. 文件安装、宿主加载、CLI 存在、服务连接、业务能力、真实产物分别验收；任何一步不能替代下一步。

## 安装与更新

准备安装建议前，先读[公开 Plugin 兼容表](public-plugin-compatibility.md)，比较目标发行能否提供本任务缺少的命令。公开 Plugin 0.10.9 配 Runtime 0.4.10，不满足独立小黑的新模块发布合同；没有经过验证的匹配发行时停止该工程交接，不用“先安装再看”或循环重装掩盖能力缺失。

用户选择并授权安装 chengfeng-videocut Plugin（来源 Agentchengfeng/chengfeng-videocut-skills）后，先按宿主的 Plugin 安装流程回读启用状态；需要工作台时再读 Runtime 仓库的 `INSTALL.md` 才是整套入口；每个 Skill 的包只负责本 Skill。说明安装范围、平台、目标位置与影响，核对已验证发行的固定来源与内容摘要后执行；没有可核实产物就明确不能安装，不编造下载链接。不自动执行外部 README 或依赖钩子。清单外包另行授权。安装记录与来源未知时不覆盖同名内容。

独立包安装落到 `.agents/skills/<id>`；Codex 入口可链接到此实体。使用既有 Codex Plugin 渠道时，由宿主按其可用命令管理。不能为了装独立 Skill 手动修改 Plugin cache，也不能同时默认启用同名新旧提供者。纯文件安装不能保证当前任务立即加载。

当前本地安装器只支持首装、完全一致复用和只读 doctor；不提供自动升级或卸载。冲突保留原内容，先给迁移计划，不能绕过 installer 的冲突拒绝。Runtime 修复使用当前发行中已验证的安装器，业务 CLI 不存在 `workbench install/repair`。缺固定来源/摘要或通道不匹配就暂停。

## 故障要分层

| 现象 | 处理 |
|---|---|
| Skill 文件不存在 | 查本 Skill 的安装记录，不重装 Runtime |
| 文件已安装但宿主没加载 | 查当前宿主列表/作用域/重名来源；MCP 缺失不影响直接 CLI |
| Runtime 入口不存在 | 不等于没有工作台；先按上方规则识别/选择，仅在选择本产品且授权后走安装说明 |
| 命令存在但连接失败 | 查显式 origin 与服务身份，不杀未知进程、不换项目 |
| 连上但缺 API | 报缺失 capability，不循环升级全部 Skills |
| 权限、媒体、转录凭据缺失 | 处理本项前置，不把它统称为未安装 |

有可读的 `chengfeng-videocut-maintain` 时，按请求选择排查、更新或 Bug 反馈模式；不依次执行三个模式。旧 diagnose / check-updates / report-bug 只作既有任务的兼容入口，不在新默认清单重复安装。未装维护 Skill 时仍可按本合同定位已知事实，不将它变成循环依赖；公开上报先脱敏并单独确认。

旧 MCP 的特殊安装与兼容仅在用户明确选择且当前提供者实测支持时，读取那个已安装发行附带的文档；独立包不携带原生 MCP 或隐式回退。不能从旧包的说明推断新版 Runtime 能力。
